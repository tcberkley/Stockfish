# Stockfish Experiment Project

## Overview

This is a fork of [Stockfish](https://github.com/official-stockfish/Stockfish) used for discovering, implementing, and testing experimental patches via [Fishtest](https://tests.stockfishchess.org/tests/run) (SPRT framework).

`src/` contains the Stockfish engine source (C++17). Key files for experiments: `search.cpp`, `movepick.cpp`, `evaluate.cpp`, `tt.cpp`, `thread.cpp`, `history.h`.

## Workflow

1. **Discover** ideas using `meta-prompt.md` thinking frameworks
2. **Queue** them in `TODO.md` (structured, machine-parseable format)
3. **Implement** via `/experiment [item-number]` skill — this builds, benches, commits, pushes the branch, and outputs Fishtest submission details. It marks the item `[SUBMITTED]` in TODO.md.
4. **Submit** — the user must manually submit the branch on https://tests.stockfishchess.org/tests/run using the details from step 3. Claude cannot do this.
5. **Analyze** results and update kill patterns

## Key Files

| File | Purpose |
|------|---------|
| `TODO.md` | Experiment queue — tiered, with READY/SUBMITTED status |
| `HISTORY.md` | Archive of killed/passed experiments with results and patterns |
| `NEXT.md` | Top 5 recommended experiments (auto-generated by orchestrator `recommend` mode) |
| `meta-prompt.md` | 11 thinking frameworks for idea generation (simplification-first) |
| `.claude/skills/experiment/SKILL.md` | `/experiment` skill — implements, benches, branches, prepares Fishtest submission |
| `.claude/agents/` | Specialized agents: searcher, advocate, skeptic, orchestrator |

## Agents

| Agent | Purpose | Invocation |
|-------|---------|------------|
| `searcher` | Explores source for anomalies and experiment opportunities | Point at a file or subsystem |
| `advocate` | Argues FOR a candidate in the adversarial debate system | Used internally by orchestrator |
| `skeptic` | Argues AGAINST a candidate in the adversarial debate system | Used internally by orchestrator |
| `orchestrator` | Manages the pipeline (modes: discover, refine, analyze, prune, status) | Specify mode |

## Conventions

- Experiment branches: `experiment/<descriptive-slug>`, single commit on top of `master`
- Commit format: subject line, 1-2 sentence rationale, `Bench: <number>` as last line
- Master bench: 2,288,704 (bench MUST differ for functional changes)
- Remote: `origin` = `tcberkley/Stockfish`, `upstream` = `official-stockfish/Stockfish`
- Build: `cd src && make -j build ARCH=native`
- Bench: `./stockfish bench 2>&1 | tail -5`
- Perft validation: must output `Nodes searched: 4865609`

## TODO.md Format

Items use `[READY]`, `[SUBMITTED]`, `[KILLED]`, `[PASSED]`, or `[MANUAL]` status tags. Diff blocks use `~~~diff` fencing. The killed patterns paragraph at the top of TODO.md is critical — always check it before proposing new ideas.

## What Works in Upstream Stockfish

Based on analysis of recent upstream commits:
- ~37% are simplifications (removing terms, conditions, code paths). They run as non-regression tests `<-1.75, 0.25>`.
- ~20% are minimal signal additions (1-3 lines, connecting existing data to existing decisions).
- ~15% are formula reshapes at high-traffic decision points.
- ~10% are code reorderings (moving logic to a different position in search).
- Successful additions typically change 1-4 lines.
- Successful contributors study recent patches and look for "ripple effects" — if A was simplified, maybe B can be too.

**Priority:** Simplifications (remove dead terms) ≈ signal additions at high-traffic points > formula reshapes > parameter tweaks. Simplifications are the most likely to pass.

## What NOT to do

- Never submit pure parameter nudges (<20% change to a single constant) without structural justification
- Never duplicate a killed pattern without explaining why the prior failure doesn't apply
- Never include markdown files in experiment branch commits
- Never modify more than one formula per experiment (clean attribution)
- Never skip studying recent upstream patches before a discovery cycle
- Never propose more than 60% additions and fewer than 30% simplifications in a discovery batch
